Why this stack

The official Odoo Docker documentation is explicit: the image needs a PostgreSQL server; extra addons mount at /mnt/extra-addons; filestore belongs in a named volume at /var/lib/odoo. That is the whole architecture.

Prerequisites

  • Docker Engine or Docker Desktop, with docker compose available
  • 4 GB RAM free (8 GB is more comfortable)
  • Ports 8069 free
  • This repository cloned locally

Check:

docker --version
docker compose version

Bring it up

cd setup
docker compose up -d
docker compose logs -f web

When the log shows the HTTP server, open http://localhost:8069. You should see the database manager, not a Python traceback.

How?
  1. Open a terminal in this repo. Run cd setup then docker compose up -d. First run downloads images — that can take several minutes.
  2. Optional check: docker compose ps. Done looks like: primer-odoo and primer-db both Up; web ports include 8069.
  3. docker compose logs -f web until you see a werkzeug / HTTP line, then Ctrl+C to stop following (containers keep running).
  4. Open http://localhost:8069.

Done looks like: the database manager form. If the tab stays blank, wait and re-check logs. Port already allocated → stop the other process or map 8070:8069.

Compose highlights (mirrors the official example: web + db, extra addons, config directory, named volumes):

services:
  web:
    image: odoo:18.0
    ports: ["8069:8069"]
    environment:
      HOST: db
      USER: odoo
      PASSWORD: odoo
    volumes:
      - odoo-web-data:/var/lib/odoo
      - ./config:/etc/odoo
      - ./addons:/mnt/extra-addons
  db:
    image: postgres:15
    environment:
      POSTGRES_DB: postgres
      POSTGRES_USER: odoo
      POSTGRES_PASSWORD: odoo

Master password is admin_passwd in setup/config/odoo.conf, default primer-master-change-me. That password is for creating and deleting databases, not for logging in as a user.

How?

Open setup/config/odoo.conf and find admin_passwd. Type that exact string into the Master Password field on the database manager — not into the Email/Password login fields after a database exists.

Done looks like: Create / Backup / Duplicate / Drop work. If those buttons reject the password, you are using the admin user password by mistake.

Create databases the primer way

  1. Master password: from odoo.conf.
  2. Database name: primer_learn.
  3. Email / login: your email. Password: pick one and store it in your password manager, not in git.
  4. Language: English. Country: United States (Harborline labs) unless you are practicing a specific localization.
  5. Demo data: checked for learn, unchecked for primer_portfolio.
How?
  1. Stay on http://localhost:8069 (or /web/database/manager).
  2. Fill Master Password from odoo.conf, Database Name primer_learn, then Email + Password (your login).
  3. Language English, Country United States for Harborline labs.
  4. Demo data checkbox: on for primer_learn. Later, a second database primer_portfolio with demo data off.
  5. Click Create database and wait.

Done looks like: you are logged in to the home / app switcher, not still on the manager form.

Filestore and database are a pair

Attachments and product images live in /var/lib/odoo/filestore/<dbname>. A SQL dump without the filestore is a half backup. A volume wipe (docker compose down -v) deletes both.

Odoo.sh — what to say, what not to run

Odoo.sh is git-push hosting with per-branch staging. It is sold with Odoo Enterprise. Community Edition is not hosted there. You still need the vocabulary for Upwork:

  • Production, staging, and development databases mapped to git branches
  • Custom modules as the git repo (or submodules), not copied into core
  • Builds on push; logs and shells in the dashboard

For this program you never pay for sh. If a job is “we are on Odoo.sh,” you work in their project after they invite you.
