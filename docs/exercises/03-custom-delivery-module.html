Demand theme

The wholesale implementation post included custom documents and Odoo Studio in scope. Other open jobs asked to “develop or modify custom modules if required” and “basic customization & automation.” Upwork catalog cards repeat “Odoo developer for customization, module development, report writing” and “Odoo Custom Module Development.” A Freelancer.com Odoo 18 customization brief (same market pattern) asked for extra fields on leads/quotes/orders and custom reports as upgrade-safe Python/XML modules with git delivery.

Studio is Enterprise. This exercise is the Community-shaped answer: a tiny module in git.

What you ship

Module primer_delivery_instruction already in setup/addons/. Your job is not to rewrite it from zero unless you want the reps. Your job is to install, demo, and pack it like a client delivery.

  • Installed on primer_portfolio. Instruction on a real Harborline SO. Fragile handling note visible on the order page and in the Primer menu.
  • Second user sales.lab is Primer User: can create, cannot delete. Screenshot of the Access Error or missing delete. Manager/admin can delete.
  • Delivery note: portfolio/delivery-module/HANDOFF.md with depends, groups to assign, and “how to upgrade.” Link to the module path in this repo.

Optional stretch (if time)

Add a boolean print_on_delivery and show it on the list. Upgrade the module. That single extra field is the “yes I can change it” moment on a sales call. Do not start a PDF report in this sitting unless you already know QWeb.

Done when

  • A reviewer can clone the repo, compose up, install the module, and see the smart button without you on a call.
  • HANDOFF.md names the groups exactly as in Settings.
  • You did not copy core sale files into the addon.

The folder setup/addons/primer_delivery_instruction/ with README. Put that folder on a public GitHub repo and use that URL as the portfolio link. Do not zip all of Odoo.

Proposal snippet

For custom fields and small documents I ship an upgrade-safe module (Python model, XML views, ir.model.access groups) in git — not core edits, not Studio-only, so you can move hosts. Example: delivery handling instructions on the sales order with User vs Manager rights.

Do not claim

OWL frontend expertise, report engines, or “20+ custom modules” until that is true. One honest module beats a fake count.
