Custom module starter

Most “can you just add a field?” jobs are module jobs. You will install a small, upgrade-safe addon that already lives in this repo: delivery instructions on the sales order, with User vs Manager rights.

45 min Prereq: Modules 1–2, Docker addons mount Produces: installed addon + ACL demo

Why custom modules beat Website for Module 5

Website and eCommerce work exists on Upwork (catalog items like “a high-conversion Odoo website,” freelancer history with “Odoo Website Updates,” “Finish a Odoo Ecommerce”). Implementation posts, though, repeatedly ask for customization, custom modules, custom documents, and Python. Project catalog cards repeat “customization, module development, report writing.” The wholesale job wanted custom documents on top of Sales/Inventory/Accounting.

A custom module is also a better GitHub artifact than a theme screenshot. You can keep Website as a later track; do not skip security and inheritance.

Rules that keep you hireable:

  • Never edit Odoo core. Extra-addons only.
  • Depend on official apps (sale_management, stock), not on copying their files.
  • Security files in the manifest before views if views need ACLs on new models.
  • Version string 18.0.x.y.z so you remember the series.

Anatomy of the lab module

Path: setup/addons/primer_delivery_instruction/

primer_delivery_instruction/
  __init__.py
  __manifest__.py
  models/
    __init__.py
    delivery_instruction.py   # _name = primer.delivery.instruction
    sale_order.py             # _inherit = sale.order
  views/
    delivery_instruction_views.xml
    sale_order_views.xml      # inherit sale.view_order_form
  security/
    security.xml              # groups
    ir.model.access.csv       # ACL

Manifest declares name, version 18.0.1.0.0, depends, and data files in load order: security XML (groups), CSV (ACL), then views. License LGPL-3 matches typical Community addons.

New model primer.delivery.instruction: name, many2one to sale.order, related partner, handling selection, state, two button methods. This is better teaching than only adding a fields.Char on sale.order, because you must write ACL.

Inheritance on sale.order: one2many, count, window action for the smart button. XML xpath injects a stat button on button_box and a notebook page.

Odoo 18 list views use <list> (tree still often works). The lab uses list.

Lab — install and break it on purpose

1. Confirm the mount (5 min)

docker compose -f setup/docker-compose.yml exec web ls /mnt/extra-addons
# expect: primer_delivery_instruction
docker compose -f setup/docker-compose.yml restart web

If the folder is missing, your compose volume is wrong. Fix that before debugging Python.

  • ls shows the module directory inside the container.

2. Read the Python (10 min)

Open delivery_instruction.py and sale_order.py. You should be able to answer: what is _name vs _inherit? Why ondelete="cascade"? Why store=True on the related partner (searchable on the list)?

_name creates a new table. _inherit patches an existing model. Doing both in one class is a different, advanced pattern (extension with a new model name) — not used here.

  • You annotated, in your tracker, one sentence each for _name and _inherit.

3. Install (10 min)

  1. Developer mode on.
  2. Apps → Update Apps List. Remove the “Apps” filter if the module is not application: True (it is a technical addon). Search “Primer Delivery”.
  3. Install. If it errors, read the traceback: CSV group xml ids, xpath, missing dependency.
  4. Refresh. App switcher should show Primer. Sales order form should show Instructions smart button and a notebook page.

Create an instruction on the Northwind SO: handling Fragile, text “Do not double-stack pallets. Call Maya 30 min out.” Confirm the record with the header button.

  • Primer menu lists the record. SO smart button count is 1.
    How?
    1. Developer mode on (Module 1: Settings → bottom → Activate the developer mode).
    2. App switcher → Apps. Remove the default Apps filter if it is on — this module is application: False, so the filter hides it.
    3. Click Update Apps List → Update. Search Primer Delivery (or technical name primer_delivery_instruction). Install.
    4. Refresh. App switcher should show Primer. Open the Northwind SO: Instructions smart button + a notebook page.

    Done looks like: module installed without a traceback, Primer menu lists the instruction, SO button count is 1.

4. Security lab (12 min)

Settings → Users: create sales.lab if needed. Grant Sales / User and Primer Delivery / User, not Manager. Log in as that user (incognito). Open an instruction. Edit text. Try delete — ACL for User is read/write/create, unlink 0. Manager has unlink 1.

Remove the Primer group entirely from a user and they should not open the model (Access Error). That is the demo you want on Loom: “here is the group, here is the CSV.”

Read ir.model.access.csv:

id,name,model_id:id,group_id:id,perm_read,perm_write,perm_create,perm_unlink
access_primer_di_user,...,model_primer_delivery_instruction,group_primer_user,1,1,1,0
access_primer_di_manager,...,model_primer_delivery_instruction,group_primer_manager,1,1,1,1

model_primer_delivery_instruction is automatic: model_ + name with dots to underscores. Group xml ids live in the same module unless prefixed with other_module.xmlid.

  • You reproduced Access Error or missing Delete as the User, and Delete as Manager (or admin).
    How?
    1. App switcher → Settings → Users & Companies → Users. Open or create sales.lab.
    2. Access Rights: Sales / User plus Primer Delivery / User — not Manager. Save.
    3. Log in as that user (incognito or another browser). Open an instruction. Edit text. Try Action → Delete (or the delete icon).

    Done looks like: User cannot unlink (button missing or Access Error). Log back in as admin/Manager: Delete works. That is the Loom: “here is the group, here is the CSV.”

5. Change, upgrade (8 min)

Add a field, e.g. priority = fields.Boolean() on the instruction model, add it to the list view, then Apps → Upgrade the module (or -u primer_delivery_instruction if you later run odoo-bin). Restart is required for Python; XML-only can sometimes live-reload depending on flags. In Docker, restart web after Python edits.

If you skip Upgrade after XML changes, you will gaslight yourself. Manifest data files load on install/upgrade, not on every page view (except views in some dev modes).

  • Screenshot pack: manifest snippet, Primer list, SO button, User denied delete.

ACL vs record rules (know the difference)

ACL (ir.model.access): can this group CRUD this model at all? Record rules (ir.rule): which rows? Example: salesperson sees only their own orders. The lab module does not add a record rule so you can see the difference. A real customer-isolation rule would be a follow-on exercise.

Empty group_id on an ACL row means everyone — usually a mistake on a new model.

Scaffold command

On a source install you would run odoo-bin scaffold my_module /path/to/addons. Official Docker does not make that convenient. Hand-built folders (this repo) are how many Community jobs actually look. If you later work on Odoo.sh, the repo is the extra-addons.

Recall prompts

Order of data files in the manifest for a new model?

Groups XML → ir.model.access.csv → views/menus. Views that assume the model is usable still need ACL loaded first to avoid access errors on install for non-admin, and groups must exist before CSV references them.

_name vs _inherit?

_name new model/table. _inherit extend existing model in place.

Why did Apps search hide your module?

Default Apps view filters application = True. This lab module is application: False. Clear the filter or search technical name.

User can read but not delete. Which file?

ir.model.access.csv perm_unlink=0 on the User group row. Not a record rule.

You changed Python and nothing happened. First restart or upgrade?

Restart the Odoo process to load Python. Then upgrade if you also changed XML/CSV or need to load new fields into the registry/database columns (new fields usually need restart; Odoo updates columns on registry load, but XML snapshots need upgrade).
