Module 01

Setup & navigation

Get a Community database you trust, learn where things live, and stop being scared of the database manager. This sitting is plumbing. Treat it like a pre-flight, not like reading the manual.

35 min Prereq: Docker Produces: running lab + UI map

Why this shows up on Upwork

Open jobs titled along the lines of “setup ERP, modules, API, data import” and “Odoo ERP Specialist” start with setup Odoo (cloud or on-premise), user access, and then CRM / Sales / Inventory / Accounting. Nobody pays for “I installed Docker” as a standalone gig. They do bounce implementers who cannot create a database, turn on developer mode, or explain Community vs Enterprise without hand-waving.

Your goal is competence you can narrate: “I stand up Community on Docker with PostgreSQL, extra-addons, named volumes; for Enterprise clients I work in their Odoo.sh.”

Concepts to retrieve later

Four products people confuse

NameWhat it isMoney
Odoo CommunityLGPL server + apps. Official Docker image is this.Software: $0. Hosting: your machine or VPS.

Process vs data

Odoo is a Python process. PostgreSQL holds records. The filestore holds attachments. Lose one of the three and you have a mystery. Compose in this repo keeps DB and filestore in Docker named volumes so docker compose down (without -v) does not wipe the lab.

Master password vs admin user

The master password (admin_passwd) gates /web/database/manager: create, duplicate, drop, backup. The admin user is a res.users row inside a database. Mixing them up is a classic first-week failure.

Apps vs modules

An app is a module with a store icon (application: True). Technical modules hide until developer mode. “Install CRM” is Apps. “Upgrade my custom module” is also Apps, after Update Apps List.

Lab

1. Start the stack (8 min)

cd setup
docker compose up -d
docker compose ps
docker compose logs --tail=80 web
  • primer-odoo and primer-db are up. Browser loads http://localhost:8069.

If 8069 is busy, change the compose port mapping to 8070:8069 and use that URL. Do not run two Odoo containers on the same port and hope.

2. Create primer_learn (7 min)

  1. Master password: primer-master-change-me unless you changed odoo.conf.
  2. Database name: primer_learn.
  3. Email + password: yours. Do not commit them.
  4. Country: United States (matches Harborline exercises).
  5. Demo data: on.
  6. Wait. First database creation downloads nothing extra but it compiles assets and loads localization. That can take a few minutes.
  • You can log in and see the home / app switcher.

3. Install the four apps this primer actually uses (6 min)

Apps → search and install CRM, Sales, Inventory, Invoicing. Also install Purchase if you want receipts from vendor POs in Module 3. Decline the urge to install Website, eLearning, and Dashboards “while you are here.” Extra apps add menus and settings noise.

  • CRM, Sales, Inventory, Invoicing show as installed.

4. Developer mode (4 min)

Settings → scroll to the bottom → Activate the developer mode. (Some versions: the bug icon after you enable it from Settings → General Settings, or add ?debug=1 to the URL.)

You now get:

  • A bug/beetle menu: Edit View, View Fields, Technical menu
  • Settings → Technical (Sequences, Parameters, User-defined defaults)
  • Apps → Update Apps List
  • Bug icon visible. Technical menu visible under Settings.

5. Users, company, language (5 min)

Settings → Users & Companies → Company: set the company name to Harborline Wholesale (lab) on the portfolio database later. On primer_learn you can leave demo company names; just know where the record lives (res.company).

Create a second user: warehouse.lab with Inventory / User rights only. You will need a non-admin user in Module 5 to prove ACL. Do it now while the Users form is in your muscle memory.

Recall prompts

Close the extra tabs. Answer without looking.

Where do product images go if you back up SQL only?

Filestore under /var/lib/odoo/filestore/<db>. SQL-only restore shows broken attachments.

You can log in as admin but cannot create a new database. What is missing?

The master password for /web/database/manager, from admin_passwd — not the admin user’s password.

A client says “we are on Odoo.sh, Community Edition.” What is wrong?

Odoo.sh hosts Enterprise. Community is Docker/VPS/on-prem. Ask which edition they actually run before quoting Studio or sh-only features.

Why did your custom module not appear after you copied a folder into addons/?

Need the volume mount, a restart so the process sees files, developer mode, then Apps → Update Apps List. Then install.

Name three things the official Docker compose example mounts or volumes.

Filestore volume on /var/lib/odoo, config dir on /etc/odoo, extra addons on /mnt/extra-addons, plus a Postgres data volume.

Done when

  • http://localhost:8069 serves your primer_learn login without errors.
  • CRM, Sales, Inventory, Invoicing are installed.
  • Developer mode is on and you can open Settings → Technical.
  • You can explain master password vs admin user in one sentence.
  • A UI-map screenshot exists on disk, not only in your head.
